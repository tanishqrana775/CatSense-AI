## 🎯 Project Overview & Problem Statement

Cat owners often misinterpret their pet's emotions because feline body language and vocalizations are subtle and complex.  
This project aims to build an **AI system** that analyzes **cat facial expressions** (images) and **meows/vocalizations** (audio) to detect four emotions:

- Happy 😺
- Sad 😿
- Angry 😾
- Fearful 😨

The system will eventually be a **Streamlit web app** (html css and jacascript alsow)here users can upload a photo or audio clip of their cat and get:
- Predicted emotion
- Confidence score (%)
- Short behavioral interpretation

**Technologies Used (as per specification)**  
- Python 3.9+
- Deep Learning: PyTorch (preferred over TensorFlow for this project)
- Image: torchvision + PIL
- Audio: torchaudio (MFCC, spectrogram — Librosa not used due to env constraints)
- Web App: Streamlit
- Others: NumPy, Pandas, Matplotlib, Seaborn

## 🚀 Deploy to Render

CatSense AI / MeowMind is pre-configured for automated 1-click or Git-driven deployment on [Render](https://render.com) using the included `render.yaml`.

### Architecture & Memory Optimization
- **Runtime**: Python 3.12 (`render.yaml` pins `PYTHON_VERSION: 3.12.7`).
- **Memory Footprint**: Models are **lazy-loaded and cached** (`OMP_NUM_THREADS=1`, `TF_CPP_MIN_LOG_LEVEL=2`). Gunicorn boots in under 1 second with <80 MB RAM, staying well below Render's 512 MB free tier ceiling.
- **Model Storage**:
  - `models/vision_model.keras`: **36.09 MB** (EfficientNetV2-B0, fine-tuned)
  - `models/audio_model.keras`: **0.31 MB** (Depthwise Separable 2D-CNN, <40k parameters)
  - *Note*: Both models are well below GitHub's 100 MB and Render's 90 MB thresholds, so regular Git commits work without Git LFS.

### Step-by-Step Deployment Steps

1. **Push your code to GitHub**:
   ```bash
   git add .
   git commit -m "Production deployment ready"
   git push origin main
   ```

2. **Connect Repository to Render**:
   - Log into [dashboard.render.com](https://dashboard.render.com).
   - Click **New +** > **Blueprint**.
   - Connect your GitHub repository. Render will automatically detect `render.yaml`.

3. **Configure Environment Variables**:
   In the Render Web Service settings, verify/add the following variables:
   - `FLASK_ENV`: `production`
   - `SECRET_KEY`: Automatically generated by Render (or paste a 32+ character random string).
   - `DATABASE_URL`: Your production PostgreSQL connection string (see Database Note below).
   - `TF_CPP_MIN_LOG_LEVEL`: `2`
   - `OMP_NUM_THREADS`: `1`

4. **Deploy**:
   - Click **Apply**. Render will run:
     - Build: `pip install -r requirements.txt`
     - Start: `gunicorn app:app --workers 1 --threads 2 --timeout 120 --preload`
   - Health check endpoint: `/healthz`

### ⚠️ Important Free-Tier Notes & Caveats
- **Cold Starts**: Render's free web service will sleep after **~15 minutes of inactivity**. The first incoming request will take **~50–70 seconds to cold start**. Subsequent requests respond in milliseconds.
- **Database Recommendation**: Render's built-in free PostgreSQL database expires after 90 days. For persistent, permanent production storage, we strongly recommend creating a free PostgreSQL instance on **[Neon](https://neon.tech)** or **[Supabase](https://supabase.com)** (serverless Postgres with SSL support). Paste the connection string (`postgresql://...`) directly into `DATABASE_URL` in your Render dashboard.
- **SQLite Fallback**: If `DATABASE_URL` is omitted, the app will operate on a local SQLite database (`cat_emotion.db`). Note that Render's local filesystem is ephemeral and resets on each deployment or restart.
